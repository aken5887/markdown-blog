개인적으로 쓸 개발 블로그를 Markdown 파일 기반으로 구성했다. 글을 데이터베이스에 넣는 대신 파일로 관리해서, 에디터나 Git으로 바로 열어볼 수 있게 한 것이 핵심이다.

## 구성

- 서버: Node.js + Express
- 프론트엔드: Vanilla JS, 별도 빌드 과정 없음
- 콘텐츠: `posts/<카테고리>/*.md`
- 프론트매터: `gray-matter`로 제목, 등록일, 수정일, 태그 파싱
- Markdown 렌더링: 브라우저에서 `marked.js` 사용
- 코드 블록: `highlight.js`로 문법 강조

## 글 데이터 흐름

글을 저장하면 서버가 제목을 파일명으로 변환해 카테고리 폴더에 Markdown 파일을 만든다. 게시글 식별자는 `posts/meta.json`에서 관리하고, 상세 페이지는 `/posts/:id` 경로로 진입한 뒤 API에서 콘텐츠를 가져와 렌더링한다.

```text
write.html → POST /api/posts → posts/개발/파일명.md
                         └→ posts/meta.json

/posts/:id → GET /api/posts/by-id/:id → post.html 렌더링
```

## 구현한 기능

### 게시글 관리

- 카테고리별 목록 조회
- 게시글 작성, 수정, 삭제
- Markdown 파일 가져오기
- 이미지 업로드 후 본문에 경로 자동 삽입
- 제목, 태그, 등록일, 수정일 메타데이터 관리

수정 시에는 최초 등록일을 유지하고 `updated` 값만 갱신하도록 처리했다. 상세 페이지에서는 등록일과 수정일을 구분자와 함께 한 줄로 보여준다.

### 조회 경험

- 제목, 본문, 태그를 대상으로 한 전문 검색
- 카테고리 탭 필터
- 다크 모드 및 테마 저장
- 작성 화면의 실시간 Markdown 미리보기

## 최근 개선 사항

### 작업 내역 기록 규칙

이 프로젝트의 기능을 수정하거나 추가한 뒤에는 이 문서에 변경 목적과 구현 내용을 간단히 기록한다. 기능 변경 후에는 로컬 서버를 재시작하고 주요 동작을 확인한다.

### 이미지 확대와 미사용 파일 정리

상세 페이지의 본문 이미지를 클릭하면 전체 화면 오버레이에서 확대해 볼 수 있다. 배경 클릭, 닫기 버튼, `Esc` 키로 닫을 수 있으며 확대 중에는 배경 스크롤을 막는다.

서버는 시작할 때 `posts/images/`의 이미지 파일을 모든 Markdown 문서와 대조한다. 일반 Markdown 경로, URL 인코딩된 공백 파일명, Obsidian 임베드처럼 파일명이 본문에 포함된 참조를 보존하고, 어느 문서에서도 참조하지 않는 이미지 파일만 자동 삭제한다.

### Obsidian과 블로그의 공용 이미지 처리

이미지 저장 위치를 `posts/images/`로 단일화했다. 블로그에서 파일을 선택하거나 브라우저 이미지를 편집기에 붙여넣으면 서버가 이 폴더에 파일을 저장하고, 본문에는 `images/<파일명>` 형식의 Markdown 경로를 삽입한다. 따라서 Obsidian과 블로그가 동일한 첨부 파일을 참조한다.

Obsidian에서 생성하는 `![[이미지.png]]`, 크기 옵션이 포함된 `![[이미지.png|400]]`도 일반 Markdown 이미지로 정규화해 렌더링한다. 공백이 포함된 파일명은 URL 인코딩을 한 번만 적용하도록 처리해 `%20`이 `%2520`으로 중복 변환되는 문제도 방지했다.

이미지 업로드 API에는 세션 인증, 이미지 MIME 타입 확인, 10MB 파일 크기 제한을 추가했다. 이미지 쓰기 역시 게시글 작성·수정과 동일한 권한 정책을 따른다.

### 편집기 작업성

원본 Markdown과 미리보기 패널을 동일한 고정 높이의 편집 영역으로 구성했다. 이미지가 많아 미리보기 본문이 길어져도 패널 전체 높이가 달라지지 않고, 각 패널 내부에서만 스크롤된다. 한쪽 패널을 스크롤하면 반대편도 전체 문서 진행률 기준으로 동기화해 긴 글을 수정할 때 현재 위치를 맞추기 쉽게 했다.

### 게시글 상세 화면

카테고리와 수정·삭제 액션을 상단 한 줄에 배치하고 제목은 다음 줄 전체 폭을 사용하도록 변경했다. 긴 제목에서도 액션 버튼이 밀리거나 줄바꿈되지 않는다. 등록일과 수정일은 `등록일 · 수정일` 형태로 한 줄에 표시한다.

### 메인 게시글 카드

메인 목록 카드는 카테고리, 제목, 요약, 태그·등록일 순서로 구성했다. 카드 하단 메타 영역은 고정해 목록마다 요약 길이가 달라도 태그와 등록일의 위치가 일정하게 유지된다.

서버에서 카드용 요약을 만들 때 코드 블록, 이미지·위키 임베드, 링크 URL, HTML, Markdown 제어 문자와 장식용 특수문자를 제거한다. 목록 화면에는 본문 내용만 남기고 최대 3줄로 자르므로, Markdown 원문이 그대로 노출되지 않는다.

## 쓰기 권한과 배포

로컬 실행 환경은 기본적으로 쓰기가 허용된다. 배포 환경은 실수로 글이 변경되는 것을 막기 위해 읽기 전용으로 시작하고, 필요한 경우 `ALLOW_WRITES=true`로 전환할 수 있다.

글쓰기 API는 공용 비밀번호 인증을 거친 세션 토큰이 있어야 호출할 수 있다. 비밀번호 해시는 `posts/auth.json`에 저장한다.

Render처럼 로컬 디스크가 유지되지 않는 환경에서는 별도 GitHub 데이터 저장소를 연결한다. 서버가 시작될 때 글과 이미지를 내려받고, 변경이 발생하면 커밋과 푸시를 수행하는 방식이다.

## 실행

```bash
npm install
npm run dev
```

서버는 기본적으로 `http://localhost:3000`에서 실행된다. 기능을 수정한 뒤에는 서버를 재시작하고 주요 API 응답을 확인하는 흐름으로 관리한다.
